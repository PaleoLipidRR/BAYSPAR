How a prediction is made

Six steps, the same in all three

Find the cellWhich 20° × 20° calibration cell holds the site. Choose draws1,000 of 20,000 posterior samples of α, β, τ². Set the priorMean of modern temperatures within 500 km. InvertA conjugate normal update for every draw. SampleOne temperature per TEX₈₆ value per draw. Summarise5th, 50th and 95th percentiles.

Analogue mode replaces the first step with a search for cells whose modern TEX₈₆ looks like the sample. The forward model runs the calibration the other way, from temperature to TEX₈₆.

Standard prediction · temperature from TEX₈₆ at a known site

bayspar_tex

bayspar_tex.mbaysparpy/bayspar_tex.pybayspar/predict.py · predict_seatemp

Turns a TEX₈₆ series from one core into temperatures. The calibration's slope and intercept come from the grid cell that contains the core, which assumes the ocean there behaved as it does today.

The math

A regression, inverted one draw at a time

Calibration, per cellTEX86 = α + β T + ε,   ε ~ N(0, τ²)
Prior on temperatureT ~ N(μ₀, σ₀²)
Posterior precisionλ = 1/σ₀² + β²/τ²
Posterior meanμ = μ₀/σ₀² + β (x − α)/τ²λ,   sd = 1/√λ

One TEX₈₆ value, one draw

The likelihood of a TEX₈₆ value x, read as a function of temperature, is a normal curve centred on (x − α)/β with width τ/β. The posterior is the precision-weighted compromise between it and the prior. Parameters here are the median draw for this site's cell; the prior mean is the one all three implementations compute for it.

priorlikelihoodposterior

Where the prior mean comes from

Each dot is a 1° cell of modern sea-surface temperature. The prior mean is the average of every cell within 500 km of the core (filled), here of them. The dashed square is the edge of the 20° calibration cell centred on (10° W, 0°) whose α and β the site uses.

Load the parameters and the climatology

MATLABReference

Reads two .mat files from ./ModelOutput on every call, so it only works when run from the repository root.

BAYSPARpySame result

The same file, found once and cached (see Data & loading).

brews/baysparpyDiffers

Choose which draws to use

The fitted model is 20,000 joint posterior draws of α, β and τ². With the default 1,000, MATLAB keeps every 20th, so the sample spans the whole chain. See Draws & percentiles for what the alternatives cost.

MATLABReference

Draws 1, 21, 41, … 20,000.

BAYSPARpyIdentical math

Same indices. np.round rounds halves to even, so the port rounds half away from zero by hand, as MATLAB does (BT-06).

brews/baysparpyDiffers

No thinning: jj runs 0 … nens−1 through its 10,000 draws, which are draws 10,001 onward of the full chain.

Prior mean from nearby modern temperatures

The average of every 1° climatology cell within 500 km of the site, by chordal distance, or the single nearest cell when none is that close.

MATLABReference
BAYSPARpyIdentical math

A stable sort keeps tied distances in MATLAB's order, which decides which cells are averaged (BT-07).

brews/baysparpyDiffers

Gives the same 26.867441 °C at this site. When nothing is within 500 km it stops on assert n_in_buffer > 0 instead of falling back to the nearest cell.

Find the calibration cell

α and β vary in space on a grid of 162 cells, each 20° × 20°. The site takes the parameters of the cell whose centre lies within 10° of it in both longitude and latitude.

MATLABDefect

The test is inclusive (<=), so a site exactly on a cell edge, such as lon 0° or lat 10°, matches two cells. A series then fails with a dimension error, and a single value silently returns two rows (BT-08).

BAYSPARpyFixes the defect

Takes the nearest centre and warns, naming both cells. strict_grid=True raises instead.

brews/baysparpyDefect

The same inclusive test. .squeeze() then hands back two rows and the loop fails further on. It also rejects lon = −180.

Invert the calibration, one conjugate update per draw

For each draw (α, β, τ²) the posterior for each sample is normal, with the closed-form mean and variance above. Samples are updated independently because the prior has no correlation in time.

MATLABReference

Tiles every term to N × 1,000 with repmat, then works element by element.

BAYSPARpyIdentical math

The same four lines, broadcast instead of tiled. The denominator does not depend on the data, so it is one number per draw rather than N × M (BT-09).

brews/baysparpySame result

The same posterior, computed with N × N matrices: a linear solve and a Cholesky factorisation for every draw. The matrices are diagonal, so the extra work buys nothing.

Sample the posterior

MATLABReference

BAYSPARpyChanged on purpose

One generator per call. seed=None keeps MATLAB's behaviour; an integer makes the run repeatable (GEN-03).

brews/baysparpySame result

NumPy's global stream, one vector per draw inside the loop.

bayspar_tex_analog

bayspar_tex_analog.mbaysparpy/bayspar_tex_analog.pybayspar/predict.py · predict_seatemp_analog

For deep time, where a core's modern position says little about its past ocean. Instead of one cell, it pools every calibration cell whose modern coretops have TEX₈₆ like the sample's, then runs the same inversion as standard mode across all of them.

The selection

Which cells count as analogues

Mean coretop TEX₈₆ in each of the 80 cells

Wilson Lake's 52 samples average . With search_tol = (twice their standard deviation), cells fall inside the window. All three implementations pick the same cells.

Where those cells are

The 162 calibration cells; outlined cells hold coretop data, filled cells are the analogues. Grey is land, drawn from the 1° climatology's coverage.

The τ² pairing defect (BTA-05), with 3 cells and 4 draws

MATLAB flattens α and β with a column-major reshape (cell changes fastest) but tiles τ² with repmat (draw changes fastest). Each column below is one flat position. Where the τ² draw differs from the α, β draw (outlined), the triple no longer comes from one posterior sample.

Line up α, β and τ² across the cells

τ² is one chain shared by every cell, so pooling has to keep each τ² with the α and β of the same draw. The diagram above shows what goes wrong.

MATLABDefect

reshape runs cell-fastest and repmat runs draw-fastest, so most α, β meet the τ² of another draw (BTA-05).

BAYSPARpyFixes the defect

Keeps α and β as a cells × draws block, so τ² broadcasts against its own draw. mode="matlab" reproduces the mis-pairing on lines 85–95.

brews/baysparpyFixes the defect

Loops over cells, then draws, indexing α, β and τ² with the same jj. Correctly paired.

Solve and summarise

MATLABReference

The standard-mode solve, run on one flat row of cells × draws.

BAYSPARpyIdentical math

Percentiles pool cells and draws together, as MATLAB does.

brews/baysparpyDiffers

The same pooling, axis=(1, 2), with 'nearest' percentiles. Its N × N solve runs once per draw per cell: 24,000 times here.

Shape of the saved ensemble

MATLABDefect

The header promises N × cells × draws. The code returns N × (cells·draws), so the second axis is not the cell (BTA-08).

BAYSPARpyFixes the defect

N × cells × draws, with axis 1 in analog_locs order: 52 × 24 × 1,000 here.

brews/baysparpyFixes the defect

N × cells × draws: 52 × 24 × 1,000.

Geometry · used by the prior-mean search and the boundary tie-break

EarthChordDistances_2

EarthChordDistances_2.mbaysparpy/distance.pybayspar/observations/core.py · chord_distance

The straight-line distance between two points on a sphere of radius 6,378.137 km, through the Earth rather than along its surface. It decides which modern temperatures count as within 500 km.

The math

Haversine half-angle, then the chord

Half the central anglea = arcsin √( sin²(Δφ/2) + cos φ₁ cos φ₂ sin²(Δλ/2) )
Chordc = 2R sin a
For comparison, the arcs = 2R a

Chord against arc

Drag to change the separation. At the 500 km search radius the two differ by about 13 metres, so the choice never changes which cells are averaged in practice.

Which percentile

Three definitions of the 5th percentile

Percentiles of the numbers 1 to 10

MATLAB's prctile places sample i at (i − 0.5)/n and interpolates (Hazen). NumPy's default places it at (i − 1)/(n − 1). brews/baysparpy uses 'nearest', which snaps to a sample. Move the slider to compare.

Thinning

MATLABReference

BAYSPARpyIdentical math

floor(x + 0.5) to match MATLAB's rounding, then 0-based. Tested at 999, 1,000 and 1,001 draws, where rounding matters (BT-06).

brews/baysparpyDiffers

Checks nens against its 10,000, then uses draws 0 … nens−1 in order. Never thins.

Percentiles

brews/baysparpyDiffers
